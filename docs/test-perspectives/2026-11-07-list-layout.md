# リスト表示と3列レイアウトのテスト観点

対象: Board.tsx、Card.tsx、Column.tsx、styles.cssの変更。

## 正常系
- must: 3列が画面幅を均等に使い、タスクを区切り線で表示する。Chromeの実画面で確認済み。
- must: タスクのタイトル・優先度・ラベル・メモとアーカイブ操作を維持する。実データの画面とアクセシビリティツリーで確認済み。

## 境界値
- should / BVA適用: 720px前後で縦並びへ切り替わり、列の最小幅を解除する。CSS確認済み、今回の変更後の端末実機検証なし。
- should / ECP適用: 空の列、長いタイトル、ラベルあり・なし、メモあり・なし。空列・長いタイトル・メモあり・なしは実画面で確認済み。大量ラベルは未実測。
- should: 4列以上では横スクロールし、タスクが多い場合は行を縮めず列内スクロールする。CSS確認済み、実データ大量投入テストなし。

## 異常系
- should: アーカイブ失敗時にボタンを再操作でき、エラーを表示する。既存の非同期処理とfinallyは維持。通信障害E2Eは未実施。

## 状態遷移
- should: 「列を追加」を開くと入力へフォーカスし、Escapeと作成完了時に閉じて操作へフォーカスを戻す。実装確認済み、操作のE2E自動テストなし。
- should: ドラッグ中の見た目、キーボード移動、並べ替え後の再表示。データの移動関数はlayout.test.tsでカバー済み。今回のDOM変更後の全入力方式の手動試験なし。

## 回帰
- must: 既存の保存・移動ロジックを壊さない。既存17テストはすべて成功。UIの全操作を自動化するテストではない。
- should: ヘッダーとダイアログの配置を維持する。ヘッダーは実画面確認済み。ダイアログの既存SSRテストはカバー済み。

## フレームワーク結合
- must: Reactとdnd-kitの実描画でul/liのリストと操作要素を構成する。mockなしの開発サーバーをChromeで開き、リストと操作がアクセシビリティツリーに現れることを確認済み。

検証: npm test（17件成功）、npm run typecheck、vite build、git diff --check。
負荷・性能テストは今回の範囲外。
